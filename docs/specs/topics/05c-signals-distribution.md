### `ORDER_REQUESTED` — Клиент прислал заказ

| Field | Value |
|---|---|
| Pack · block · family | distribution · DS1 · order |
| Weight · class · kind · score rule | 7 · chance · event · fixed |
| Effort · asks us · inbound only · amount | quick · yes · yes · yes |
| Emitted by | parser |
| Stage (pack default) · IN4COM | active · on |
| Display profile | from weight (D4) + deadline escalation: same-day shipment → «Сейчас» (decided R8, 2026-11-13) |
| Recipient role | account (draft: sales) |
| Closes / closed by | closes: — · closed by: `ORDER_CONFIRMED` (same topic); made moot by `ORDER_CANCELLED` (Open point 11) |
| Relations | outranks `STOCK_AVAILABILITY_REQUEST` and `SALES_PRICE_REQUEST` on the same subject; `ORDER_CANCELLED` outranks it; replaces base `SALES_BOOKING_RECEIVED` (off for IN4COM) |
| Date gate | — |
| Relevance window | 14 days — an order that is not confirmed in 14 days was processed outside the CRM or is lost; the card must not stay open longer |
| Deal effect | none (Q26). Topic and card only. Later step: «Создать заказ» on the card (replaces the `new_order` card) |

**Определение:** Клиент (закупщик, сомелье, управляющий, бар-менеджер) присылает заказ на поставку: называет позиции и количество (бутылки, коробки) и просит отгрузить, привезти или выставить счёт. Сюда же относится повтор прошлого заказа («как обычно», «как в прошлый раз») и заявка файлом.

**Граница (не считается):** Вопрос о цене или наличии без просьбы отгрузить → `SALES_PRICE_REQUEST` / `STOCK_AVAILABILITY_REQUEST`. Изменение уже отправленного заказа → `ORDER_CHANGE_REQUESTED`. Бронь товара, которого ещё нет (новый урожай, будущий контейнер) → `PREORDER_REQUESTED` (предложено). Наше собственное предложение, наша заявка поставщику, подтверждение заказа от нашего поставщика нам (мы покупатель → блок N). Напоминание по уже отправленному заказу («подтвердите, что заявку получили») — не новый код, а обновление той же темы.

**Признаки для промпта (≤ 8):** «прошу отгрузить», «заказ на», «нужно 12 кор.», «по 6 бут.», «выставьте счёт на», «сделайте заявку», «закажем как обычно», «закиньте в заказ»

**Синонимы и выражения (полный список):**
- Деловая переписка: «прошу отгрузить», «просим поставить», «направляем заказ», «заявка на поставку», «заказ на следующую неделю», «прошу выставить счёт на следующие позиции», «прошу зарезервировать и отгрузить», «просим доставить к пятнице», «во вложении заявка», «повторите, пожалуйста, прошлый заказ», «прошу включить в ближайшую отгрузку», «просим привезти по адресу ресторана на Покровке»
- Чаты / мессенджеры (разговорный стиль): «закиньте в заказ», «скиньте счёт на», «нам на пятницу», «привезите», «закажем как обычно», «как в прошлый раз, только шабли побольше», «давайте 2 кор. просекко и кор. риохи», «плиз, на завтра», «оформите нам», «надо 6 бут. брюта до выходных», «запишите на четверг», «берём»
- Сокращения и термины: «кор.», «бут.», «бт», «шт.», «ящ.», «0,75», «магнум 1,5», «арт.», «артикул», «код товара», «урожай 2021», «21-го года», «заявка», «счёт на оплату», «спецификация к заказу»
- Устойчивые конструкции / маркеры: «прошу / просим + отгрузить / поставить / привезти» + список позиций с количеством; «нужно / надо + число + кор. / бут.»; «на + день недели / дату» (желаемый срок); таблица «наименование — количество» во вложении или в теле

**Похоже, но не это (анти-признаки):** «есть ли шабли 21-го?» → `STOCK_AVAILABILITY_REQUEST`; «пришлите прайс» → `SALES_PRICE_REQUEST`; «добавьте ещё кор. к заказу» → `ORDER_CHANGE_REQUESTED`; «заказ подтверждаем, счёт во вложении» (наше письмо) → `ORDER_CONFIRMED`; «готовы взять в карту три позиции» → `LISTING_OPPORTUNITY`; «поставьте нас в лист ожидания на новый урожай» → `PREORDER_REQUESTED`.

**Пример (evidence):** «Добрый день! Прошу отгрузить к пятнице: Шабли 2021 — 12 кор. по 6 бут., Просекко DOC — 3 кор. Счёт на ООО «Ромашка».»
**Контрпример:** «Подскажите, почём сейчас Шабли 2021 и сколько его у вас на складе?» → нет просьбы отгрузить; это вопрос о цене и наличии.

**Заметка для карточки:** Пишите «Ответственный менеджер — подтвердить заказ клиента и дату отгрузки»; укажите позиции, количество и срок клиента, если они есть в сообщении.

### `ORDER_CHANGE_REQUESTED` — Клиент просит изменить заказ

| Field | Value |
|---|---|
| Pack · block · family | distribution · DS1 · order |
| Weight · class · kind · score rule | 6 · risk · event · fixed |
| Effort · asks us · inbound only · amount | quick · yes · yes · yes |
| Emitted by | parser |
| Stage (pack default) · IN4COM | active · on |
| Display profile | from weight (P6) |
| Recipient role | account (draft: sales) |
| Closes / closed by | closes: — · closed by: `ORDER_CONFIRMED` (same topic) |
| Relations | `ORDER_CANCELLED` outranks it; attaches to the order topic by order number or by the open order topic of the same client (same family, 14 days) |
| Date gate | — |
| Relevance window | 14 days (same as the order) |
| Deal effect | none (Q26) |

**Определение:** Клиент просит изменить уже отправленный заказ: добавить или убрать позицию, поменять количество, заменить вино на другое, перенести дату или адрес отгрузки.

**Граница (не считается):** Новый отдельный заказ на другие позиции или другую дату → `ORDER_REQUESTED`. Полная отмена → `ORDER_CANCELLED`. Перенос отгрузки — это изменение, а не отмена. Просьба подобрать замену позиции, которой нет у нас на складе → `SUBSTITUTION_REQUESTED` (предложено). Жалоба на уже доставленный товар → блок DS4.

**Признаки для промпта (≤ 8):** «добавьте в заказ», «уберите позицию», «замените на», «перенесите отгрузку», «вместо 12 сделайте 8», «докиньте кор.», «поменяйте адрес доставки», «скорректируйте заявку»

**Синонимы и выражения (полный список):**
- Деловая переписка: «просим внести изменения в заказ», «прошу скорректировать заявку № 154», «прошу исключить из заказа позицию», «просим увеличить количество», «прошу заменить Риоху Крианса на Резерву», «прошу перенести отгрузку на понедельник», «доставку просим перенести на другой адрес», «уточнение к заказу», «прошу считать актуальной заявку во вложении»
- Чаты / мессенджеры (разговорный стиль): «докиньте ещё кор. просекко», «уберите брют», «вместо 12 сделайте 8», «давайте не в пятницу, а в субботу», «в заказ ещё 2 бут. магнума», «поменяйте на розе», «минус одна кор.», «закиньте ещё позицию, плиз», «привезите не на Тверскую, а на Арбат»
- Сокращения и термины: «корректировка заказа», «новая редакция заявки», «доп. позиция», «перенос отгрузки», «изменение адреса доставки»
- Устойчивые конструкции / маркеры: «добавьте / уберите / замените / перенесите» + ссылка на существующий заказ («в заказ», «к заявке», «в сегодняшнюю отгрузку»)

**Похоже, но не это (анти-признаки):** «и ещё отдельный заказ на следующую среду» → `ORDER_REQUESTED`; «отгрузку не делайте, заказ отменяем» → `ORDER_CANCELLED`; «шабли нет, чем можно заменить?» → `SUBSTITUTION_REQUESTED`; «привезли не ту позицию» → `DELIVERY_DISCREPANCY`.

**Пример (evidence):** «По заявке 154: Шабли вместо 12 сделайте 8 кор. и добавьте 2 кор. Кремана. Отгрузку перенесите на понедельник.»
**Контрпример:** «Получили заказ 154, всё на месте, спасибо» → изменение не просят; нет сигнала.

**Заметка для карточки:** Пишите «Ответственный менеджер — внести изменения в заказ и подтвердить клиенту новый состав и дату»; перечислите, что меняется.

### `ORDER_CANCELLED` — Клиент отменил заказ

| Field | Value |
|---|---|
| Pack · block · family | distribution · DS1 · order |
| Weight · class · kind · score rule | 7 · risk · event · fixed |
| Effort · asks us · inbound only · amount | quick · no · yes · yes |
| Emitted by | parser |
| Stage (pack default) · IN4COM | active · on |
| Display profile | from weight (P6) |
| Recipient role | account (draft: sales) |
| Closes / closed by | closes: — (makes `ORDER_REQUESTED` / `ORDER_CHANGE_REQUESTED` on the same topic moot, Open point 11) · closed by: — (the user marks «Готово» after the reserve is released) |
| Relations | outranks `ORDER_CHANGE_REQUESTED` and `ORDER_REQUESTED` on the same subject |
| Date gate | — |
| Relevance window | default |
| Deal effect | none (Q26) |

**Определение:** Клиент отменяет уже отправленный заказ целиком или просит не отгружать его.

**Граница (не считается):** Перенос даты («перенесите на следующую неделю») → `ORDER_CHANGE_REQUESTED`. Удаление одной позиции → `ORDER_CHANGE_REQUESTED`. Отказ от нового предложения, а не от заказа → `SALES_OFFER_DECLINED`. Отказ от наших позиций в карте вообще → `DELISTING_RISK`. Отказ принять доставку из-за боя или пересорта → `DELIVERY_DISCREPANCY` / `RETURN_REQUESTED`.

**Признаки для промпта (≤ 8):** «отменяем заказ», «заказ не нужен», «не отгружайте», «аннулируйте заявку», «снимите заказ», «отбой по заказу», «пока ничего не везите», «отзываем заявку»

**Синонимы и выражения (полный список):**
- Деловая переписка: «просим отменить заказ № 154», «прошу аннулировать заявку», «заказ больше не актуален», «отзываем заявку на поставку», «просим не осуществлять отгрузку», «в связи с закрытием ресторана заказ отменяем», «счёт оплачивать не будем, заказ отменён», «просим снять резерв»
- Чаты / мессенджеры (разговорный стиль): «отбой по заказу», «не везите», «заказ не нужен», «снимите заказ», «отменяем всё», «пока ничего не надо, отбой», «не грузите, мы передумали», «сорри, отмена»
- Сокращения и термины: «аннулирование заказа», «снятие резерва», «отмена заявки», «отказ от поставки»
- Устойчивые конструкции / маркеры: «отменяем / аннулируем / отзываем + заказ / заявку»; «не + отгружайте / везите / грузите»

**Похоже, но не это (анти-признаки):** «перенесите на вторник» → `ORDER_CHANGE_REQUESTED`; «уберите из заказа брют» → `ORDER_CHANGE_REQUESTED`; «предложение не подходит» → `SALES_OFFER_DECLINED`; «выводим ваши вина из карты» → `DELISTING_RISK`.

**Пример (evidence):** «Коллеги, заказ на пятницу отменяем, банкет перенесли. Не отгружайте, пожалуйста.»
**Контрпример:** «Банкет перенесли, отгрузку сдвиньте на 20-е» → заказ остаётся, меняется дата; это `ORDER_CHANGE_REQUESTED`.

**Заметка для карточки:** Пишите «Ответственный менеджер — снять резерв и выяснить у клиента причину отмены»; не предполагайте причину, если клиент её не назвал.

### `ORDER_CONFIRMED` — Мы подтвердили заказ / выставили счёт

| Field | Value |
|---|---|
| Pack · block · family | distribution · DS1 · order |
| Weight · class · kind · score rule | 0 · — · state · state |
| Effort · asks us · inbound only · amount | — · no · no · yes |
| Emitted by | both — parser (our outbound mail / chat) now; process (order status `confirmed` in the CRM, no LLM) in the orders step |
| Stage (pack default) · IN4COM | active · on |
| Display profile | S0 — closes, no card |
| Recipient role | — |
| Closes / closed by | closes: `ORDER_REQUESTED`, `ORDER_CHANGE_REQUESTED` on the same topic; after approval of DS7 also `PREORDER_REQUESTED`, `SUBSTITUTION_REQUESTED`, `MIN_ORDER_ISSUE` · closed by: — |
| Relations | attaches to the order topic by order / invoice number; never creates a topic (spec §6.2 step 6) |
| Date gate | — |
| Relevance window | — |
| Deal effect | none (Q26) |

**Определение:** Мы (сотрудник организации) подтверждаем клиенту заказ: принимаем его в работу, называем дату отгрузки или высылаем счёт / УПД на этот заказ.

**Граница (не считается):** Подтверждение заказа от нашего поставщика нам — это не этот код. Наш ответ «уточняем наличие» без подтверждения не закрывает заказ. Сообщение клиента «заказ подтверждаем» — это клиент подтверждает свой заказ (часть `ORDER_REQUESTED`), а не мы.

**Признаки для промпта (≤ 8):** «заказ принят», «подтверждаем заказ», «счёт во вложении», «отгрузка запланирована на», «заказ собран», «поставили в отгрузку», «резерв сделали», «привезём в пятницу»

**Синонимы и выражения (полный список):**
- Деловая переписка: «ваш заказ принят в работу», «подтверждаем заказ № 154», «направляем счёт на оплату», «во вложении счёт и спецификация», «отгрузка запланирована на 14.11», «товар зарезервирован», «заказ включён в рейс на четверг», «доставка будет в интервале с 10 до 14»
- Чаты / мессенджеры (разговорный стиль): «принято», «заказ взяли», «счёт скинули», «поставили на пятницу», «всё есть, привезём завтра», «собрали, едет», «резерв сделали»
- Сокращения и термины: «счёт», «УПД», «спецификация», «резерв», «рейс», «маршрут», «отгрузка»
- Устойчивые конструкции / маркеры: наше сообщение + «принят / подтверждаем / зарезервирован / запланирована» + ссылка на заказ или дату

**Похоже, но не это (анти-признаки):** «ваш заказ у поставщика подтверждён» (письмо поставщика нам) → нет сигнала / блок N; «уточним наличие и вернёмся» → нет сигнала; «товар доставлен, накладные подписаны» → нет сигнала (доставка, не подтверждение).

**Пример (evidence):** «Заказ 154 принят, счёт во вложении. Отгрузка в пятницу, 14.11.»
**Контрпример:** «Заявку получили, проверяем остатки» → заказ ещё не подтверждён; тема остаётся открытой.

**Заметка для карточки:** Карточку не создаёт. В истории темы пишите «Заказ подтверждён, отгрузка <дата>».

**Заметка для карточки:** Пишите «Ответственный менеджер — договориться с клиентом о встрече по карте и стартовой закупке новой точки»; укажите дату открытия, если она названа.

## DS7 · Предложено дополнительно

**Status of this block: `proposed (new)`.** These codes are not in the draft. They fill gaps that the draft leaves for a wine distributor. Pack stage = `onHold` and IN4COM = `review` until the IN4COM users confirm them (Q25). Weights are new proposals (no source value exists). Each entry says which draft block it belongs to after approval.

Reasons in short:
- `LISTING_CONFIRMED` — the draft has deal **entry** codes (listing, new venue) but no code for the **win**; without it a listing deal can be won only by hand, and the risk «Клиент выводит позиции» has no clear code.
- `DECISION_POSTPONED` — the risk «Решение откладывается» (04 §4) needs a postponement trigger; base has only meeting codes, and the agency `PITCH_DECISION_DELAYED_BY_CLIENT` is not in this pack.
- `ALLOCATION_REQUESTED`, `PREORDER_REQUESTED` — scarce wines and new vintages are sold by quota and pre-order; such requests are neither an order nor a stock question.
- `SUBSTITUTION_REQUESTED` — an out-of-stock position is the most common cause of a lost line in an order.
- `MIN_ORDER_ISSUE` — the minimum order / paid delivery dispute is a daily friction point with small HoReCa clients.
- `EXCISE_PRICE_QUERY` — excise and minimum-retail-price (МРЦ) changes make clients ask about new prices and stock up before the date.
- `EXCLUSIVITY_REQUESTED` — exclusive rights on a position are a term of listing deals in HoReCa and chains.

**Признаки для промпта (≤ 8):** «эксклюзив», «только у нас», «не поставляйте конкурентам», «эксклюзивное право», «эксклюзив в городе», «чтобы у соседей не было», «эксклюзивная позиция для сети», «условие — эксклюзивность»

**Синонимы и выражения (полный список):**
- Деловая переписка: «просим рассмотреть эксклюзивное право на позицию в Санкт-Петербурге», «условием ввода является эксклюзивность в канале сетевой розницы», «готовы взять бренд в карту при условии эксклюзива в районе», «просим не поставлять позицию другим ресторанам на улице»
- Чаты / мессенджеры (разговорный стиль): «дадите эксклюзив?», «хотим, чтобы это было только у нас», «соседям не возите, ок?», «если эксклюзив — берём», «чтобы в городе больше ни у кого не было»
- Сокращения и термины: «эксклюзив», «эксклюзивность», «эксклюзивный дистрибутор», «канал», «территория», «СТМ»
- Устойчивые конструкции / маркеры: «эксклюзив / эксклюзивность + на позицию / бренд / город / сеть»; «не поставляйте + конкурентам / соседям»

**Похоже, но не это (анти-признаки):** «сколько нам выделите из лимитки» → `ALLOCATION_REQUESTED`; «у соседей это же вино дешевле» → `COMPLAINT_PRICE`; «нужна СТМ под нашу сеть» → `LISTING_OPPORTUNITY`.

**Пример (evidence):** «Готовы ввести ваш Гави в карту, но при условии эксклюзива в нашем районе — соседям его не поставляйте.»
**Контрпример:** «Это вино у вас кто-то ещё в городе берёт?» → вопрос без просьбы об эксклюзиве; нет сигнала.

**Заметка для карточки:** Пишите «Ответственный менеджер — согласовать внутри решение по эксклюзиву и ответить клиенту»; укажите позицию и территорию.

## Closing and attachment logic

Rules from spec §2.1 (rules 4–7), §6.2 and §7.3 apply. A closing code acts only **on the same topic**. It never creates a topic; with no matching topic it is stored on the item and logged (spec §6.2 step 6).

### Closers

| Closing code | Profile | Closes on the same topic | Attaches by |
|---|---|---|---|
| `ORDER_CONFIRMED` | S0 | `ORDER_REQUESTED`, `ORDER_CHANGE_REQUESTED`; after DS7 approval also `PREORDER_REQUESTED`, `SUBSTITUTION_REQUESTED`, `MIN_ORDER_ISSUE` | order number / invoice number; else the open order topic of the same client (family `order`, 14 days) |
| `DELIVERY_DISCREPANCY_RESOLVED` | S1 | `DELIVERY_DISCREPANCY`, `RETURN_REQUESTED`, base `COMPLAINT_QUANTITY` | delivery date, ТТН / УПД / claim number; else the open delivery topic of the same client |
| `EGAIS_ISSUE_RESOLVED` | S1 | `EGAIS_ISSUE`, `MARKING_ISSUE` | ТТН number; else the open ЕГАИС topic of the same client |
| base `INVOICE_PAID` | S0 | base `INVOICE_OVERDUE` and (pack seed adds it) `PAYMENT_PROMISE` | invoice / УПД number; else the open invoice topic of the same client |
| base `SALES_OFFER_SENT` | S0 | base `SALES_OFFER_REQUESTED` (unchanged) | offer number; else the open offer topic |
| `LISTING_CONFIRMED` (proposed) | S1 | `LISTING_OPPORTUNITY`, `NEW_VENUE_OPENING`, `DELISTING_RISK`, `EXCLUSIVITY_REQUESTED`; deal outcome `won` | contract / tender number; else the open listing or venue topic of the same client |

### Codes that attach to an existing topic

| Code | Attaches to | Effect on that topic |
|---|---|---|
| `PAYMENT_PROMISE` | the open `INVOICE_OVERDUE` topic of the same client (hard key: invoice / УПД number) | history record «обещал оплатить к <дата>»; relation `dampens` (06 §5.2 H4): the invoice topic goes one list level down until the promised date + 1 working day, and it stays visible; if `INVOICE_PAID` does not arrive, the dampener ends and a new cycle starts. It never closes the invoice topic (a promise is not a payment). Without an open invoice topic it makes its own W1 topic. |
| `ORDER_CHANGE_REQUESTED`, `ORDER_CANCELLED`, `SUBSTITUTION_REQUESTED`, `MIN_ORDER_ISSUE`, `DELIVERY_SCHEDULE_REQUEST` | the open order topic of the same client (order number, else family `order` within 14 days) | UPDATE of the order card; `ORDER_CANCELLED` becomes the lead (risk beats chance at weight 7) |
| `RETURN_REQUESTED` | an open `DELIVERY_DISCREPANCY` topic of the same delivery, if one exists | one claim, one card |
| `DOCUMENTS_REQUESTED` | an open delivery / discrepancy / ЕГАИС topic of the same shipment, if one exists; else its own topic | the document request is a step inside that claim |
| `DECISION_POSTPONED` (proposed) | the deal topic (listing, venue, tender, contract) | counts toward the risk «Решение откладывается» |
| a reminder («ну что по заказу?», «когда замените?») | the topic it reminds about | no new code; UPDATE with `waiting_on_us` (spec §2.1 rule 5) |

### Quick asks without an own closing code

`STOCK_AVAILABILITY_REQUEST`, `SAMPLES_REQUESTED`, `TASTING_REQUESTED`, `PROMO_SUPPORT_REQUESTED`, `DELIVERY_SCHEDULE_REQUEST`, `DOCUMENTS_REQUESTED`, `PAYMENT_TERMS_REQUEST`, `RECONCILIATION_REQUESTED`, `ALLOCATION_REQUESTED`, `EXCISE_PRICE_QUERY`: our outbound reply on the topic sets the sub-state `waiting_on_them` (spec §7.1). The topic stays `open` until «Готово», expiry or a closing rule. Recommendation (Open point 11): a code flag `closes_on_outbound_reply` for these quick asks.
